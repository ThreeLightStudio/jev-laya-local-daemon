Why this exists

Start Laya once. Use it from any local app.

Laya normally runs inside Python. Without laya-local-api, every project would need to load the model and manage Python itself. This project moves that work into one small local server that stays running and can be shared by your other apps.

What we actually tested

The useful discovery: wording matters.

When we passed raw flags and numbers, Laya's answers barely changed. When we described what those facts meant in short plain-language sentences, the model reacted much more clearly.

How to use it

Let normal code gather facts. Give Laya one clear, small decision.

The model worked best after the app had already gathered the facts and turned them into a short, clear description of the current situation.

1 Gather facts

Git state, tests, known changes, how old the analysis is.

→
2 Explain them simply

Use simple templates to turn raw facts into short sentences.

→
3 Ask Laya

Ask it to pick one option, rate something, or answer yes/no.

→
4 Decide what to do

Your app owns the cutoff, fallback, and final action.

“Code gathers the facts. Simple templates explain what they mean. Laya handles the small decision. Your app decides what to do with the answer.”

What it is good at

Use it for narrow decisions, not as a tiny all-purpose AI.

Good fit

  • Choosing one of a few known next actions
  • Retry / skip / inspect / escalate decisions
  • A cheap first check before calling a larger model
  • Small handoff decisions between AI workers
  • Choosing what to do first from a short summary

Poor fit

  • Understanding an entire project from scratch
  • Long-form generation
  • Problems that need many reasoning steps
  • Figuring out rich meaning from raw numbers and flags alone
  • Treating one probability as a universal confidence score

Run it locally

Give your coding agent one prompt.

Let the agent handle the environment, install, port check, startup, and verification. The daemon stays on your own computer at a loopback address.

Agent setup prompt Copy, paste, run. 
Set up laya-local-api on this machine from https://github.com/ThreeLightStudio/laya-local-api.

If the repository is not already checked out, clone it into an appropriate local development directory. Use Python 3.11–3.13, create a .venv, and install the project with `pip install -e .`.

Start `laya-local-api` bound to a loopback address only. Use port 8787 unless it is already occupied. If 8787 is in use, do not stop an unrelated process; choose another available local port with `LAYA_PORT` and use that port consistently.

Wait until `GET /ready` returns HTTP 200 with `"ready": true`, then run the included `scripts/smoke.py` against the selected endpoint. If you changed the port, set `LAYA_API_URL` for the smoke test. Keep the daemon running after verification if your environment supports a persistent process; otherwise give me the exact command to start it again.

When finished, report the final local API URL, the selected port, the smoke-test result, and how to stop the daemon. Do not bind to 0.0.0.0 or expose the service to the public network.

Current conclusion

Laya is useful when the question is narrow and the choices are clear.

laya-local-api makes that model easy to reuse from local apps while leaving the final action in your own code.
